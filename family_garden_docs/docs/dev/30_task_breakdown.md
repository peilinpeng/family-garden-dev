# 30｜开发时间线与任务拆分

## 1. 总体节奏

比赛提交截止：7 月 15 日。

推荐节奏：

```text
6.11—6.15：两人预开发，完成策划、架构、资产规范、AI 输出格式、第三人接手包
6.16—6.23：三人并行开发，跑通核心闭环
6.24—6.30：Beta 版本，完成主要场景和 AI 功能整合
7.01—7.08：修 bug、优化体验、美术统一、移动端测试
7.09—7.15：演示视频、文档、截图、最终提交
```

## 2. 团队角色

### A：产品统筹 + 美术体验负责人

适合负责：

- 产品定位；
- 功能边界；
- 场景体验；
- 美术资产规范；
- 美术资产生产；
- 用户流程；
- 演示脚本；
- 参赛文案。

### B：AI 模块 + 内容安全负责人

适合负责：

- AI 记忆卡片；
- 漂流瓶问题生成；
- 房间照片识别；
- prompt；
- JSON 输出；
- mock 数据；
- 内容安全规则。

### C：游戏系统 + 后端稳定负责人

适合负责：

- 场景系统；
- 节点生成；
- SlotManager；
- NodeFactory；
- 上传流程；
- 存储接入；
- AI 中转接入；
- Web/移动端测试；
- bug 修复。

## 4. 6.16—6.23 三人并行开发阶段

目标：跑通核心闭环。

### A 重点

- 导入/修正美术资产；
- 完成家庭花园、鱼塘、房间 P0 视觉；
- 检查 UI 是否适合手机横屏；
- 持续补资产给 C 测试；
- 开始准备演示故事线。

### B 重点

- 接真实 AI 或准备 mock；
- 生成记忆卡片；
- 生成漂流瓶问题；
- 识别房间照片；
- 输出结构化 JSON；
- 失败时返回 mock。

### C 重点

- 用 mock JSON 生成地图节点；
- 实现家庭花园基本交互；
- 实现鱼塘漂流瓶交互；
- 实现 AI 房间 objects 映射；
- 接入上传/存储；
- 接入 AI 中转；
- 完成手机横屏和桌面 Web 初测。

### 6.23 验收

必须能演示：

```text
上传照片或使用预设照片
↓
AI/mock 生成记忆卡片
↓
用户回答问题
↓
家庭花园生成记忆花
↓
进入鱼塘打开漂流瓶
↓
进入个人房间查看 AI 房间物件
```

## 5. 6.24—6.30 Beta 阶段

目标：从“能跑”变成“有比赛完成度”。

任务：

- 完成家庭花园、鱼塘、AI 房间三大 P0 场景；
- 尽量完成爷爷农场或老街其中一个；
- 接入真实 AI，保留 mock；
- 图片上传与 COS/CDN 或现有存储跑通；
- 修复明显交互问题；
- 做第一次完整录屏。

6.30 验收：

- 在线打开；
- 手机横屏可操作；
- 桌面网页可操作；
- 主流程不崩；
- 有稳定演示数据；
- 至少 3 个核心场景可展示。

## 8. 每日同步模板

每个人每天同步一次：

```text
昨天完成：
今天交付：
当前卡点：
需要谁配合：
是否影响主流程：
```

不要只说“我在做”。必须说清楚“今天交付什么”。

## 9. 每周重点检查

### 6.15 检查

- 第三人接手包是否完整；
- AI JSON 是否定稿；
- P0 美术是否有第一批；
- 任务看板是否明确。

### 6.23 检查

- 核心闭环是否跑通；
- AI 或 mock 是否能生成节点；
- 鱼塘和房间是否可进入。

### 6.30 检查

- Beta 是否能完整演示；
- 手机横屏是否可用；
- 是否开始准备视频。

### 7.08 检查

- 功能冻结；
- 只修 bug 和包装。

## 10. 三人协作成功标准

1. 每个模块有明确 owner；
2. 每个交付物有验收标准；
3. 美术资产当天交 C 测试；
4. AI 输出格式提前固定；
5. C 不等待真实 AI，先用 mock 开发；
6. 6.23 以后不再大幅改主线；
7. 任何人卡住超过半天必须同步。
