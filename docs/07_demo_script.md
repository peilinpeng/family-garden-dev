# 07｜比赛与秋招面试演示脚本

> 目标时长：4 分 30 秒；最长不超过 5 分钟。
> 主线：一个异地生活的孩子，和家人共同把零散回忆变成可生长的家庭空间。

## 1. 核心表达

评委看完后只需要牢牢记住两句话：

> Family Garden 是一个 AI 驱动的数字家庭第三空间。
>
> AI 不替家人编故事，而是帮助家人更容易把故事说出来。

演示不平均介绍所有按钮。每个镜头只服务于一条闭环：

```text
家人共同进入 → AI 整理记忆 → 家人补充故事 → 空间随记忆生长 → 一起照料
```

## 2. 录制前状态

- 使用 1280×720 或 1920×1080 横屏录制，浏览器缩放 100%；
- Web 演示链接添加 `?demo_hour=14`，将拍摄画面稳定在下午，同时保留正常版本的实时昼夜；
- 关闭浏览器书签栏、系统通知、聊天软件浮窗和密码提示；
- 准备一张家庭旅行照片、一张房间照片，文件名使用中文且不含隐私；
- 主设备使用“孩子”角色，显示名字建议为“佩林”；
- 家庭邀请码、备用照片和演示文案放在录制设备旁，不在画面里临时寻找；
- 提前打开第二个家庭成员实例；若实时演示不稳定，使用已经准备好的成员状态和录屏兜底；
- 先完整彩排三次，再开始正式录制。

备用输入：

- 记忆文字：“去年夏天，我们一起去了海边。爸爸第一次学会用拍立得，妈妈在傍晚捡了很多贝壳。”
- 记忆回答：“最开心的是傍晚一起沿着海边走，爸爸拍下了大家都没有看镜头的那一刻。”
- 漂流瓶回答：“小时候爸爸常带我去河边散步，我们会在桥下停下来听水声。”

## 4. 逐字旁白稿

很多家庭并不是联系不上，而是不知道怎样自然地开始交流。照片和故事散落在手机相册、
聊天记录和云盘里，也很少有机会被一家人重新发现和共同补充。

Family Garden 是一个 AI 驱动的数字家庭第三空间。家庭成员通过同一个邀请码进入属于
自己的花园，在这里看见彼此是否在线，也能知道家人正停留在哪个场景。

当用户上传一张家庭照片或写下一段回忆，AI 会把已经提供的内容整理成一张可编辑的
记忆卡片，并提出一个温和、开放的问题。AI 不判断家庭关系，不评价感情，也不替家人
编造事实。确认之前，它只是一份草稿；确认之后，这段记忆才会进入家庭空间，并在花园里
长成可以回看的记忆花。

当两段记忆出现共同的人、地点或时间线索，AI 会提出关联建议，花园里也会长出一根
记忆藤蔓。真正的故事仍由家庭成员补写和确认。

房间照片也可以成为空间的一部分。AI 只识别书桌、台灯、植物等关键物件和区域，
不直接输出游戏坐标；客户端再从受控素材库生成安全、可探索的瓦片房间。

家庭成员还可以共同照料一块农田。一个人种下记忆种子，另一个在线成员会看到同一地块
更新。鱼塘里的漂流瓶，则把一次认真谈心变成轻巧的发现。回答会成为新的岸边记忆，
继续留在这个家庭空间里。

在 Family Garden 中，AI 是记忆整理助手，游戏是交流发生的空间。随着家人持续上传、
回答和共同照料，家庭记忆会真正长成一座花园。

## 5. 镜头语言

- 每次打开面板后停留 1 秒，给评委读标题的时间；
- 鼠标移动要慢且有目的，不在画面中来回寻找按钮；
- loading 至少保留 0.8 秒，让 AI 参与真实可见；超过 5 秒可剪短，但不要伪装成瞬时结果；
- 新记忆花、藤蔓、房间和农场刷新都要留出完整反馈，不在动画开始前切镜头；
- 产品画面占主导，技术架构只在末尾或提交文档中出现，不打断家庭故事；
- 音乐低于旁白 12—16 dB，保留少量点击和生长音效；
- 转场使用直接切换或 6—10 帧淡化，不使用花哨特效。

## 6. 现场演示压缩版

现场只有 90 秒时，按以下顺序：

1. 花园全景和“家人”面板；
2. 已准备好的 AI 记忆卡片；
3. 记忆花与藤蔓；
4. 已生成的语义房间；
5. 共享农场刷新；
6. 回到花园，用一句话收尾。

不要在 90 秒现场版临时上传大图。上传与 AI 生成由正式视频证明，现场重点证明游戏可玩、
数据存在、多个场景形成闭环。

## 7. 失败兜底

| 风险 | 画面内处理 | 演示切换 |
|---|---|---|
| AI 响应慢 | 保留“正在整理记忆”状态，说明会自动降级 | 切到已生成卡片 |
| AI 技术失败 | 展示明确 fallback 来源，不把错误伪装成真实 AI | 使用演示种子数据继续 |
| 图片上传失败 | 保留文字输入，选择“不带照片保存” | 使用已上传的记忆 |
| Web 文件选择被拦截 | 再点击一次页面打开原生选择器 | 切桌面版或预生成房间 |
| 实时成员未连接 | 展示成员列表和现有同步记录 | 使用双端录屏片段 |
| 共享地块冲突 | 展示“地块刚被家人使用”的刷新提示 | 换空地块继续 |
| Demo 页面暂时不可用 | 不反复刷新等待 | 播放本地最终录屏 |

## 9. 秋招面试现场版（推荐 6—8 分钟）

生产地址：
[`https://familygarden-d7gy18huh87fd41d2-1449262000.tcloudbaseapp.com/`](https://familygarden-d7gy18huh87fd41d2-1449262000.tcloudbaseapp.com/)

### 9.1 开场定位（30 秒）

> 这是我负责 AI 模块、游戏系统、数据与云端链路的全栈项目。它不是让 AI 替家庭编故事，
> 而是把照片、文字和家人的补充整理成可继续互动的数字家庭空间。前端使用 Godot Web，
> 服务端运行在 CloudBase，AI 输出经过 Schema 校验和内容安全，再由客户端转成受控游戏内容。

### 9.2 推荐操作顺序

1. **登录与隔离（45 秒）**：输入显示名和家庭邀请码进入，打开“家人”面板；说明成员令牌、
   `family_id` 数据隔离，以及前端不保存 service role key。
2. **AI 记忆闭环（2 分钟）**：打开“记忆”，上传准备好的旅行照片和备用文字，等待可编辑草稿，
   确认后回到花园查看记忆花，再回答 AI 追问；强调“模型只整理用户提供的信息，用户确认后才落库”。
3. **语义房间（1 分钟）**：上传房间照片，展示语义网格与生成结果；说明 AI 不输出坐标，
   只返回物件与区域，客户端使用白名单资产和规则布局，降低不可控生成风险。
4. **双端实时协作（1 分钟）**：两台浏览器使用同一家庭邀请码进入农场，让账号 A 移动或更新地块，
   账号 B 观察在线成员与刷新；说明 WebSocket 只传 Presence 和轻量变更事件，业务真值仍从网关重拉。
5. **鱼塘与旅行（45 秒）**：回答漂流瓶，再打开旅行地图，展示保存的地点与明信片，证明功能不是孤立页面。
6. **工程收尾（45 秒）**：说明真实 AI、离线 mock、受控 fallback、自动化门禁、分片 Web 发布和生产回滚备份。

### 9.3 面试官追问时的技术回答

| 追问 | 回答重点 |
|---|---|
| 为什么选择 Godot Web？ | 同一套场景与交互可导出桌面和 Web；代价是首包和移动浏览器内存，需要拆分 PCK/WASM、缓存和真机回归。 |
| 如何避免 AI 幻觉？ | AI 不决定坐标和最终事实；输入先做约束，输出做 JSON Schema 校验，用户确认后才保存，失败走明确标记的 fallback。 |
| 多人数据如何一致？ | Presence Relay 负责在线状态与轻量事件；收到 `world_changed` 后客户端通过 Data Gateway 重拉受权限控制的数据。 |
| 密钥如何保护？ | AI Key、CloudBase 管理凭据只存在服务端环境变量；客户端只持成员令牌，仓库和 Web 包不写入密钥。 |
| 如何保证现场不翻车？ | 生产发布前跑 26 项全量检查、Web 导出审计、HTTPS E2E 和真实云端双账号 smoke；现场另备已生成数据与录屏。 |

### 9.4 开场前 2 分钟检查

- 使用无痕窗口打开生产地址，确认首屏、字体、音频启动按钮和横屏恢复正常；
- 主账号和第二账号使用同一测试家庭，提前进入一次农场，确认在线人数变化；
- 手机 Safari/Chrome 依次验证竖屏提示、旋转到横屏、取消照片选择、重新选择测试照片；
- 浏览器缩放 100%，关闭通知、密码弹窗、书签栏和开发者工具；
- 本地保存一张无隐私旅行照片、一张房间照片，以及本文件第 2 节的三段备用文字；
- AI 超过 5 秒仍无结果时说明 fallback 设计并切到已生成记录，不在现场连续刷新或重复提交。

### 9.5 收尾（15 秒）

> 可多人协作的完整产品链路，同时处理了 Web 游戏的性能、移动适配和生产发布问题。
