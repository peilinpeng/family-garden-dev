# 20｜UI：记忆卡片 Memory Card

## 1. UI 作用

记忆卡片是 AI 输出和家庭故事展示的核心界面。用户点击记忆花、照片牌、明信片或房间物件后，都可以打开记忆卡片。

它要清楚展示：

- 这段记忆是什么；
- AI 观察到了什么；
- AI 提出了什么问题；
- 家庭成员如何回答；
- 这段记忆属于哪个场景或节点。

---

## 2. 卡片字段

| 字段 | 必须 | 说明 |
|---|---|---|
| title | 是 | 记忆标题 |
| image | 可选 | 用户上传图片 |
| description | 是 | AI 温和描述 |
| question | 是 | AI 问题 |
| answer | 可选 | 用户/家庭成员回答 |
| uploaded_by | 可选 | 上传者 |
| memory_type | 可选 | 旅行、童年、老家、房间等 |
| scene | 可选 | 所属场景 |
| close_button | 是 | 关闭 |
| answer_button | 是 | 回答或补充 |

---

## 3. 布局建议

横屏 1280×720 中，记忆卡片可以作为底部或中心弹窗。

推荐布局：

```text
┌──────────────────────────────┐
│ 标题                         │
│ 图片区域        描述区域      │
│              AI 提出的问题    │
│ 回答输入/已有回答             │
│        [补充回忆] [关闭]      │
└──────────────────────────────┘
```

手机横屏下不要放太多文字。描述控制在 1—3 句，问题控制在 1 句。

---

## 4. 文案规则

记忆卡片文案要温和，不要评判。

推荐表达：

- “这看起来像是一段家庭旅行的记忆。”
- “你还记得这一天发生过什么有趣的事吗？”
- “这张照片可以被放进家庭花园里，成为一朵新的记忆花。”

避免表达：

- “你们一家关系很好。”
- “这一定是你最幸福的一天。”
- “爸爸当时其实很孤独。”
- “这说明你们有代际创伤。”

---

## 5. 状态

| 状态 | 表现 |
|---|---|
| loading | AI 正在整理记忆 |
| ready | 卡片已生成 |
| answer_empty | 等待用户回答 |
| answered | 显示用户回答 |
| error | 使用 fallback 文案 |

## 7. 验收标准

1. 点击节点后能打开；
2. 标题、描述、问题显示完整；
3. 可以关闭；
4. 可以回答；
5. 回答后状态更新；
6. 手机横屏下不溢出；
7. AI 失败时显示 fallback；
8. 文案温和自然。
