## 1. 负责人范围与协作边界

### 1.1 系统负责人完整范围

系统负责人对以下链路端到端负责：

```text
Godot 功能入口
  → 用户文字 / 图片输入
  → 客户端状态与输入校验
  → Serverless 云函数
  → 混元模型 / 内容安全
  → 结构化输出校验
  → 数据持久化与同步
  → 场景内功能表现
  → 错误恢复 / 离线 fallback
  → 自动测试 / 部署 / 监控 / 文档
```

具体包括：

- 记忆卡片、漂流瓶问题、房间照片分析、跨记忆关联；
- `AIClient`、AI HTTP backend、Serverless AI 云函数、prompt、Schema、内容安全；
- `MemoryManager`、`CloudManager`、CloudBase 数据网关、身份、同步与冲突处理；
- Slot / Zone / Node / Room 等功能管理器及其数据契约；
- 功能性面板、加载状态、错误提示、生成反馈和 fallback 提示；
- 多成员实时状态、共享数据同步和远端成员可视化的数据入口；
- Godot 4.7 Web 导出、回归测试、部署与运行手册。

### 1.2 场景负责人范围

两位搭档继续负责各自认领场景的：

- `.tscn` 结构；
- 背景、前景、物件和动画资产；
- Y-Sort、碰撞、遮挡与场景布局；
- manifest 中属于场景的坐标、slot、zone 和 portal 落点；
- 场景自测与视觉验收。

### 1.3 唯一对接面

系统功能与场景通过以下接口对接：

- manifest：slot / zone / portal / asset catalog；
- 数据层方法：创建、读取、更新和同步业务数据；
- 场景 metadata：交互类型、提示文案、功能 ID；
- 公共 prefab：动态记忆节点、远端玩家、可交互物件。

原则：**坐标归场景，逻辑归系统；场景不直接访问后端，系统不擅自重排场景布局。**

## 3. 总体推进顺序

```text
Gate 0  仓库与运行基线
  ↓
Gate 1  AI / 数据 / 错误契约定稿
  ↓
Gate 2  AI Serverless 基础设施
  ↓
Gate 3  Godot AI 客户端与通用状态机
  ↓
Gate 4  四项 AI 产品功能完整接入
  ↓
Gate 5  CloudBase 统一存储、离线同步与并发安全
  ↓
Gate 6  实时多人
  ↓
Gate 7  室内语义场景生成
  ↓
Gate 8  测试、可观测性、发布与运维闭环
```

规则：

1. Gate 0—3 必须顺序完成；
2. Gate 4 的四个功能可在公共基础完成后逐个交付；
3. Gate 5 的统一存储是 Gate 6 实时多人之前置条件；
4. Gate 7 可在 Gate 4 房间分析稳定后启动；
5. Gate 8 的测试从 Gate 1 起持续补充，最终单独做发布验收；
6. 任一 Gate 未达到退出条件，不以“之后再补”为理由直接宣布完成。

### 7.1 目标

- [ ] 请求结束后释放临时节点；
- [ ] 支持场景切换时取消或忽略旧回调；

- [ ] `_validate_memory_card()`；
- [ ] `_validate_bottle_questions()`；

- [ ] `_validate_memory_link()`；

- [ ] 校验失败记录明确原因；
- [ ] mock 也必须通过相同验证器。

### 7.4 状态机

每次请求必须可区分：

```text
idle → loading → success
               ↘ fallback
               ↘ error
               ↘ cancelled
```

工作项：

- [ ] 定义统一结果对象；
- [ ] 记录 `source`（ai / fallback）；
- [ ] 记录 `fallback_reason`；
- [ ] 记录 request ID、模型和 prompt 版本；
- [ ] UI 可订阅加载、完成和错误状态；
- [ ] 用户可重试可重试错误；
- [ ] 同一按钮快速点击不会创建重复请求。

### 7.5 缓存与去重

- [ ] 为图片和文字输入生成内容 hash；
- [ ] 相同输入的并发请求合并；
- [ ] 对稳定分析结果使用有限缓存；
- [ ] 缓存可按 prompt / model 版本失效；
- [ ] 不长期缓存不必要的私人原始输入。

### 7.6 退出条件

- [ ] 四个接口均可通过真实 HTTP backend 调用；
- [ ] 四个接口均可独立 fallback；
- [ ] UI 能区分真实 AI 与 fallback；

## 16. 第一轮迭代：真实记忆卡片最小完整闭环

> 用户输入一段家庭记忆，真实混元生成结构化记忆卡片，Godot 校验并让用户确认，结果保存到 CloudBase 并生成花园节点；混元、网络、上传或 CloudBase 任一环失败时，用户仍可重试、手动完成或使用明确标识的 fallback。

### 16.1 任务清单

- [ ] 定稿 memory-card 请求与响应 Schema；
- [ ] 准备正常、边界、非法和不安全样例；
- [ ] 实现 AI 云函数公共入口；
- [ ] 实现混元文字生成 provider；
- [ ] 实现 memory-card prompt v1；
- [ ] 实现后端输出校验；
- [ ] 实现输入输出内容安全；
- [ ] 实现 Godot AI HTTP backend；
- [ ] 启动时注入 `AIClient`；
- [ ] 实现客户端 memory-card validator；
- [ ] 增加真实创建记忆入口；
- [ ] 增加 loading / retry / fallback / cancel 状态；
- [ ] 增加用户预览和编辑确认；
- [ ] 确认后写入 `MemoryManager`；
- [ ] 写入 CloudBase；
- [ ] 创建花园 node 并分配 slot；
- [ ] 重启后恢复；
- [ ] 增加断网、超时、非法 JSON 和 CloudBase 失败测试；
- [ ] 更新部署和验收文档。

### 16.2 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 纯文字 + AI 正常 | 生成真实卡片，确认后入库并长出节点 |
| 图片 + 文字 + AI 正常 | 图片与文字共同生成卡片 |
| AI 超时 | 显示可重试提示，可选择 fallback 或手动填写 |
| AI 返回非法 JSON | 不入库，自动重试一次，之后进入 fallback |
| 内容不安全 | 不调用或不采用生成结果，显示安全提示 |
| CloudBase 失败 | 本地保存并进入待同步队列 |
| 重复点击提交 | 只创建一条记忆和一个节点 |
| 场景切换中返回 | 不向已销毁 UI 回调，不产生半条数据 |
| 重启游戏 | 卡片和节点可恢复 |
| 无 AI backend | 完全离线可创建手动或 fallback 记忆 |

### 16.3 第一轮完成标志

- [ ] 真实 AI、客户端、数据层和场景表现形成完整闭环；
- [ ] 后续漂流瓶、房间和关联功能可以复用同一套基础设施；
- [ ] 不再需要为每个 AI 功能重复实现 HTTP、错误处理和 fallback。
