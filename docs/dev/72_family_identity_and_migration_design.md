# 72 家庭身份、邀请与存量迁移设计

> 2026-11-03；负责人：xiongweiluo。对应 O1-01，状态：设计草案，尚未实现或部署。
> 用户已授权整体迭代；下列为封闭试用的建议默认值，配置可调整，不是现网能力。
> 生产迁移的前置条件：核实环境、完成备份及隔离恢复核对、确定旧家庭实际所有者。

## 1 现有链路与问题

- `data_gateway/index.js` 的 `join_family` 仅凭公开 `family_id` 建立成员和明文令牌。
- `resolveMember` 根据令牌查询成员，没有设备、撤销、过期或独立管理权限。
- AI `services/identity_client.js` 通过 `whoami` 验证身份；这一接缝可复用。
- Presence `server.js` 在 hello 时验证一次，现有连接不会因之后撤销自动失效。
- 客户端 `cloudbase_backend.gd` 将令牌存到设备存档；`cloud_service.gd` 负责加入和初始化。
- 通用表接口允许客户端提交过多字段，且人物角色不能代表管理权。

不能单独关闭旧加入入口就算完成：还需要新家庭如何建立、合法旧用户如何恢复、失败重试
如何避免重复建号，以及被撤销的在线连接何时断开。

## 2 默认产品边界和权限

封闭试用先由运营脚本签发一次性“创建家庭凭证”，不开放匿名无限创建家庭。新成员通过
管理员邀请加入。家庭标识仅用于定位；邀请码是独立随机秘密，不与家庭 ID 相同。
人物 `role` 保留现有六种表现身份；新增 `permission` 表示 `owner/admin/member`。

| 操作 | owner | admin | member |
|---|---|---|---|
| 读取家庭共享记录、创建自己的内容与回应 | 是 | 是 | 是 |
| 修改或删除自己的内容 | 是 | 是 | 是 |
| 修改他人原文 | 否 | 否 | 否 |
| 隐藏违规共享内容（保留审计） | 是 | 是 | 否 |
| 邀请普通成员、撤销本人创建的邀请 | 是 | 是 | 否 |
| 撤销任意家庭邀请 | 是 | 是 | 否 |
| 移除普通成员并撤销其设备 | 是 | 是 | 否 |
| 任免管理员、移除管理员、转移所有权 | 是 | 否 | 否 |
| 撤销自己的其他设备、退出家庭 | 是* | 是 | 是 |
| 读写他人私有背包、读取任何凭证明文 | 否 | 否 | 否 |

* 最后一位 owner 不能直接退出或被移除；先转移所有权。家庭销毁属于单独的数据删除流程。
共享仓与农场继续走已有服务端事务，不允许通过通用 upsert 覆盖。旧记录缺少作者时默认
只读，不能把首次编辑者自动认作原作者；由受审计的迁移映射解决。

## 3 服务端数据模型（新增集合，不直接批量改写现有业务记录）

| 集合 | 核心字段及约束 |
|---|---|
| `family_security` | 家庭 ID、owner_member_id、schema_version、状态、member_count、member_limit；管理权不写进通用可写的 families 表 |
| `family_invites` | 凭证摘要、family_id、created_by、expires_at、max_uses、used_count、revoked_at；不允许客户端指定 permission |
| `member_sessions` | 随机设备令牌摘要、member_id、family_id、expires_at、revoked_at、created_at；原始令牌仅签发时返回 |
| `identity_operations` | operation_id 摘要、请求指纹、结果引用和到期时间；支持事务幂等与断线恢复，不存原始凭证 |
| `family_creation_grants` | 运营预置凭证摘要、到期时间、是否已消费；只允许服务端管理 |
| `members` 增量字段 | permission、status、auth_version、迁移状态；保留 member_id 和旧业务引用 |

凭证使用服务端密码学随机源生成至少 32 bytes；数据库只存 SHA-256 摘要。随机凭证不是
用户密码，不设计短数字码作为唯一认证因素。凭证不放 URL query，不写日志、埋点或 PR。
索引与事务支持需在目标环境验证；身份相关集合必须为 ADMINONLY，不加入通用读写白名单。

试用建议配置：邀请默认 24 小时、默认单次使用、家庭上限 12 人、设备会话最长 30 天；
允许管理员按配置范围缩短期限。实际值在隔离 smoke 前记录，不能依赖客户端传值或本机时间。
请求级限速与家庭成员上限相互独立；源地址只取平台可信信息，不能信任任意转发头。

## 4 接口契约与原子边界

所有写操作必须带稳定 `operation_id`。同 ID 不同规范化请求内容返回 409。服务端决定
member_id、family_id、permission、created_by、时间和状态。错误只返回稳定分类与 request_id。

| action | 请求重点 | 返回／原子语义 |
|---|---|---|
| `create_family` | creation_grant、名称、role、display_name、operation_id | 同事务消费创建凭证、创建安全元数据与 owner、签发设备会话 |
| `create_invite` | 已认证、有效期／次数、operation_id | 验证管理权，返回一次性可见邀请凭证与有效期；不能提升接收者权限 |
| `revoke_invite` | 已认证、invite_id、operation_id | 验证归属与管理权；重复撤销幂等 |
| `join_family`（新版） | invite_token、role、display_name、operation_id | 同事务验证有效期／撤销／剩余次数／家庭容量，增加成员与会话并消费次数 |
| `whoami` | Bearer 设备令牌 | 校验会话、成员、家庭状态，返回身份和 permission，绝不返回凭证 |
| `list_devices` / `revoke_device` | 已认证、自己的 session_id | 返回脱敏设备信息；撤销后下一次 HTTP 请求被拒绝 |
| `rotate_session` | 已认证、operation_id | 原子签发新会话并撤销旧会话；重试恢复机制见下文 |
| `remove_member` / `leave_family` | 已认证、目标、operation_id | 权限校验、成员停用及其会话失效原子生效；保留共享内容的历史署名 |
| `transfer_ownership` | owner、活跃目标成员、operation_id | 同家庭 owner 转移与权限更新原子完成，不出现无人管理窗口 |

加入失败不得消费邀请或留下孤立成员。并发兑换最后一个名额只能有一个成功；事务重试中
生成的随机结果不能每次变化。客户端在请求前持久化 operation_id 和恢复材料，完成后清理。

**响应丢失是实施前必须完成的设计验证点：** 邀请已消费但签发响应丢失时，不能再次消费
或仅凭 operation_id 领取令牌。拟采用客户端生成的独立恢复秘密绑定本次操作，服务端存摘要；
恢复时验证恢复秘密与请求指纹，给同一成员轮换设备会话。恢复秘密持有者拥有本次操作恢复权，
不因邀请码后来被撤销而无限续签；操作记录限定短时窗口，超期由管理员重新邀请／受控恢复。
需先做丢包、重放和两个客户端竞争恢复的测试，再定稿具体字段；未验证前不实现生产迁移。

无凭证旧客户端调用 `join_family` 返回稳定 `INVITE_REQUIRED`；用户界面引导输入邀请，
不得静默回落到公开家庭。存在有效旧会话的用户可在迁移兼容窗口内更新客户端并换取新版会话。
设备丢失时由管理员确认原成员身份后签发绑定该 member_id 的一次性恢复凭证；不自动通过
同昵称、同人物角色或同家庭 ID 恢复。owner 全设备丢失由运营核验处理，不能自动选第一位成员。

## 5 AI、内容写入与 Presence 的一致性

AI 继续通过 `whoami` 验证，在付费调用前完成鉴权，撤销身份不能使用缓存结果绕过验证。
生成成功不代表允许直接共享；普通写接口新增按表字段白名单、作者／管理权限校验，服务端
字段禁止客户端覆盖。AI 摘要和用户正文的共享审核都必须覆盖直接调用写接口的绕过路径。

审核选择：使用服务端直接审核待共享内容，避免把可信决策交给客户端。耗时审核在提交事务前
执行，批准结果绑定规范化正文与关联图片摘要；事务提交前检查身份仍有效且内容指纹一致。
审核失败或不可用时保留设备草稿，不共享。复用批准结果需要版本、内容摘要、家庭／成员绑定
与期限，禁止“同 operation_id 换内容”。具体审核服务、预算及图片摘要来源在 O1-04/O3-02
结合现有 AI 链路实现，不新增未经验证的付费依赖。

Presence 拟采用短期授权租约：hello 验证后每 30 秒重新验证，单次请求超时 5 秒；未能
续租则最多 45 秒停止接收／发送家庭数据并关闭连接。移动和广播入口也检查租约，不能仅靠
定时器延迟关闭。假时钟测试撤销边界和在途 hello；真实双连接验证作为 O1-03 验收。
这是建议可配置上限，未实现前不宣称支持在线撤销；具体开销在隔离环境测量。

## 6 存量迁移与发布顺序

1. 登录后只读盘点环境、集合、索引、成员、设备和备份；记录数量与脱敏校验摘要。
2. 导出并在隔离环境恢复；核对业务引用及照片可达性。备份失败则停止迁移。
3. 由实际负责人确认每个真实家庭的 owner 和成员名单；历史演示成员不能自动获得管理权。
4. 先部署支持新旧令牌读取、撤销检查和新集合的服务端；不开放未经验证的匿名创建。
5. 运行幂等 dry-run 迁移脚本输出受限清单，审核后增量建立安全元数据；保留原 member_id。
6. 发布可输入邀请、展示恢复／同步状态的新客户端；为合法旧成员进行受控会话交换。
7. 关闭无邀请新加入；关闭前必须已验证邀请、过期、容量、重放、恢复和客户端降级路径。
8. 在记录明确日期的兼容窗口结束后，删除旧明文令牌字段，验证全部旧令牌不可访问。

回滚只能回到仍强制邀请与撤销的安全服务端；禁止重新部署公开 ID 即可加入的版本。
新字段保持可读取，业务数据恢复需单独核对迁移后写入；不能用旧备份覆盖新增记录。
以上是操作计划，当前未执行任何数据迁移、旧令牌清理或生产部署。
