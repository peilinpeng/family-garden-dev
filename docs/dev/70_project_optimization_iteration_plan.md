## 2 优先级与完成定义

| 优先级 | 含义 | 处理要求 |
|---|---|---|
| P0 | 非预期家庭访问、生产服务不可用，或已确认的严重数据损坏 | 优先核实和限制影响；安全缺口关闭前不得恢复开放加入或扩大真实数据试用 |
| P1 | 可能导致记录丢失或覆盖、核心流程不可完成、现有产品承诺未兑现 | 对应发布范围必须完成；不能仅以测试总数通过豁免 |
| P2 | 性能、AI 质量、易用性、可维护性和运维效率 | 建立基线后按收益推进 |
| P3 | 新内容、更多装扮和高成本扩展 | 真实试用证明需要后再安排 |

状态统一为：待开始 → 方案已确认 → 开发中 → 待验收 → 已验收。依赖缺失标为阻塞并写明解除条件；提交了代码不等于已验收，历史通过也不自动继承到新版本。

每项完成必须同时具备：行为达到目标、失败路径可恢复、适用测试通过、必要文档更新、版本证据齐全、责任人确认。生产相关项还需单独标记“未部署／已部署未验收／生产已验收”。

5. AI 接口变更同步契约、Schema、mock、客户端解析和测试；模型不输出坐标。
6. 本轮优化范围已由 2026-11-03 用户明确授权，历史“7.08 后只修 bug 和包装”的阶段限制不阻止本计划执行；保留不删除功能、不大规模重构等持续规则。
7. 单人依次推进：同时在制任务上限为一个核心实现加一个验收收尾；外部阻塞时只推进无依赖的任务，并记录偏离顺序的原因。

合计约 **41—67 个净工作日**，另留约 25% 风险缓冲，规划容量约 **52—84 个工作日**。按每周 5 个完整工作日约 11—17 周，试用观察、设备等待和审核等待可能进一步影响日历时间。原估算未包含另由场景搭档承担的工作。现改为全部单人负责，需补计场景、美术和人工验收的容量，O0 核实后重估；上述 52—84 个工作日不能直接当成新的单人总工期承诺。

估算包括实现、相关测试、评审修改和文档，不包括重建丢失的云环境数据、采购设备或新建大量美术资产。O0 后重新估算一次，每阶段结束再校准；任务预计超过 3 个净工作日应拆为可验收子任务。

推荐主执行顺序：O0 → O1 → O2 → O3 → O4 → O5 → O6 → O7 → O8。以下工作可以提前，但不取消依赖：

- O2 的查询失败保护和存档备份可以在 O1 等待评审时独立实施。
- O3 的不可重试错误修复可提前作为单点 PR；跨实例额度不能先于身份契约定稿。
- O4 的触控原型、O6 的用户流程设计、O7 的性能测量可从 O0 后准备。
- 生产恢复必须保留安全限制；不能先恢复旧的无邀请校验加入接口，再等待 O1。

## 7 O2 同步与存档可靠性

**目标：** 临时故障不变成空数据，并发和重试不静默覆盖，用户内容可恢复。负责人：系统负责人。

| 编号 | 工作项与依赖 | 验收条件 |
|---|---|---|
| O2-01 | O0 后定义快照的逐表状态、完整性与分页契约；修复查询异常返回成功空数组 | 查询失败、超时、未知集合错误不会覆盖可信缓存；成功空表仍能正确同步；错误有稳定分类 |
| O2-02 | O2-01 后实现分页、稳定顺序和完整快照应用策略 | 0、1、1000、1001、2500 条合成记录完整读取；中间页失败不部分替换；并发写入期间不因分页漂移误删本地记录 |
| O2-03 | O2-01 后将重要普通写入纳入持久化 outbox，成功后广播；增加用户可见同步状态 | 断网和重启后待办仍在；失败可重试；清空待办只发生在服务端确认后；同一记录顺序确定 |
| O2-04 | O1-04、O2-03 后增加原子版本检查、冲突处理与删除同步规则 | 两端修改不会无提示覆盖；旧副本不复活已删除记录；删除与新编辑冲突有确定行为 |
| O2-05 | O2-03 后明确持久化幂等窗口及操作记录保留策略 | 同 operation_id 的不同内容被拒绝；超时重试不重复扣减或创建；超过现有 32 条近期操作后重放仍符合明确的业务规则 |
| O2-06 | O0 后补本地临时写入、备用存档、版本迁移、损坏恢复和保存失败反馈 | 截断 JSON、写失败、旧版存档和浏览器刷新都有测试；坏文件保留；不能因读取失败悄悄生成并覆盖新存档 |
| O2-07 | O1 权限完成后补数据导出、云端删除语义、照片关联清理和定时备份恢复 | 导出只包含授权数据；删除明确作用域；失败可重试且不误删被引用图片；自动备份成功并在隔离环境恢复核对 |

**预计文件：** Data Gateway 及测试、`cloudbase_backend.gd`、`cloud_service.gd`、`memory_manager.gd`、`ai_workflow_manager.gd`、`inventory_manager.gd`、设置与同步状态 UI、数据模型与备份脚本。按“查询／写入／存档／备份”拆 PR，不能一次修改整个数据层。

**关键决策：** 快照失败不能被当成无数据；云端确认前的乐观状态不能被下一次旧快照抹掉。分页的一致性选择版本水位或其他可验证方案；具体数据库能力先验证。删除采用 tombstone 或等效可恢复操作，保留期与退出家庭规则在实施前确定。

**备份初始目标：** 建议试用阶段 RPO 不超过 24 小时、RTO 不超过 4 小时，需负责人确认成本后冻结。RPO 表示可接受的数据时间窗口，RTO 表示从故障开始到恢复可用的时间。一次恢复“丢失 0 条”不代替持续 RPO。照片与数据库引用关系一并核验，备份放在仓库外并限制访问。

**退出条件：** 失败快照不覆盖、双端并发不静默丢写、重放不重复执行、损坏存档可恢复；定时备份与失败告警至少完成一个周期和一次隔离恢复；关键测试加入 CI。

**发布与回滚：** 先添加可选字段与兼容读，再切新写路径；旧客户端写入须受版本保护。任何同步异常先暂停覆盖并保留 outbox／原存档；不要恢复旧数据库快照覆盖新产生的数据。结构清理和永久删除安排在兼容窗口结束后的独立任务。

**预计文件：** `game/export_presets.cfg`、Web shell、资源 manifest、`tools/`、`e2e/`、`.github/workflows/quality.yml`；快照与存档优化限相关模块。未使用资源先排除出包，删除素材须另行确认。

**性能门槛：** O7-01 后冻结具体预算。初始建议为低档目标手机稳态至少 30 FPS；相同条件下首次可操作时间较基线改善至少 20%，关键场景帧时间和内存不回退超过 10%。这些是候选目标，不是当前成绩；如果无法同时满足，依据测量与产品取舍调整并留理由，不为达数牺牲资源完整性。

首次可操作时间定义为导航开始到角色可以移动、主要入口可以响应的时间，单独记录用户点击音频解锁前的等待；主线与纯演示存档分组测量。内存比较采用同一平台可观测指标，不能将不同浏览器的不同内存口径直接合并。数据可靠性与安全测试中的允许丢失、重复扣减和越权次数均为零，不使用性能目标的协商空间豁免。

**告警最小集合：** 公开入口／Presence 可用性、认证失败异常、快照错误、outbox 长时间未确认、备份失败、AI 失败／fallback 比例和费用预算。先使用合成故障验证告警能送达，不默认新增无人维护的监控平台。

**退出条件：** 性能预算有前后对照；生产依赖审计与 CI 门禁通过；发布与回滚在隔离环境演练；运行手册能由另一人执行。大文件只按真实变更需要整理，不安排新一轮全项目重构。

**回滚：** 保留完整旧构建及清单；先上传资源再切入口；数据库兼容独立验证，回退前端不等于回退数据。故障期间保护认证页、管理页与用户上传。

## 16 风险管理与范围控制

| 风险 | 提前信号 | 应对 |
|---|---|---|
| 云环境已经失效或数据不可找回 | 无法列出旧环境／存储／备份 | 停止假设可原地恢复，先形成数据恢复与新环境方案；重估工时 |
| 旧客户端绕过新限制 | 旧构建仍可不经邀请加入或覆盖新版记录 | 服务端强制约束；必要时要求更新；保留安全的只读或本地体验 |
| outbox、删除、快照互相冲突 | 数据重现、顺序颠倒、重复执行 | 先定义状态机与操作语义，再实现；用故障注入测试约束 |
| 设备或评审人不足 | 真机项长期只剩截图 | 提前预约设备和验收人；不能用桌面视口替代真机完成标记 |
| 系统负责人负荷过大 | 同时打开多个核心 PR、频繁切模块 | 限制在制工作；明确预留单人的视觉和人工验收时间；按阶段减少范围 |
| 优化演变成重构 | 没有用户收益却改大量无关文件 | 拆回最小行为任务；结构维护独立排期 |
| 新资源抵消性能收益 | 包体／内存持续增长 | 增量资源预算和导出门禁；新增内容需要说明性能成本 |
| 测试通过但实际流程失败 | 测试只断言方法存在或图片非空 | 为用户结果加断言和跨端验收；保留人工主流程 |

本轮不主动扩展：新引擎、整体重写、微服务拆分、支付商城、大量新地图、强制实时协作、复杂推荐系统、未验证必要性的向量数据库。父母更多装扮、额外场景和高级视觉效果进入 P3 候选池，不占用安全与数据可靠性阶段。

## 17 首批任务与启动顺序

1. **O0-01／O0-02：** 核对 4 个提交与云环境，形成版本矩阵和恢复选择。先做只读工作，不发布旧构建。
