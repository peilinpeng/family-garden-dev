# 33｜48 小时 Soft Pixel Art 试产规范

> 版本：v1.1（2026-06-11）
> 用途：决定比赛版本美术风格是否正式切换为 soft pixel art（方案 C′ 的风格部分）。
> 关联：`docs/09_godot_coordinate_art_spec.md` 第 2.3 节（生效条件与回退）。

## 1. 试产目标

用 8 张图走通完整流水线「AI 概念图 → Converter 像素化 → Aseprite/Piskel 修整 → 登记 manifest → 导入 Godot 真机验证」，回答三个问题：

1. 单张资产的真实耗时是多少（决定 P0 约 30 件资产是否来得及）；
2. 不同资产经过同一调色板和密度规则后，风格是否统一；
3. 2x Nearest 显示在手机横屏真机上是否可读、是否是我们要的治愈氛围。

试产**不写任何游戏逻辑**，只验证美术管线。截止：开始后 48 小时内出结论。

## 2. 试产资产清单

| # | 资产 | 源图尺寸（美术像素） | 导入后显示（逻辑像素） | 状态数 |
|---|---|---|---|---|
| 1 | 家庭花园背景 `scene_garden_bg_px_01` | 640×360 | 1280×720 | 1 |
| 2–4 | 记忆花 `node_garden_memory_flower_01_{new/read/grown}` | 48×48 | 96×96 | 3 |
| 5–6 | 漂流瓶 `node_fishpond_bottle_01_{closed/open}` | 40×40 | 80×80 | 2 |
| 7 | 照片牌 `prop_garden_photo_board_01_empty` | 64×64 | 128×128 | 1 |
| 8 | 主角行走 sheet `char_player_walk_px_01`（基于现有 `game/assets/characters/girl.png` 转换） | 每帧 32×40，整张 96×160（3×4 帧） | 每帧 64×80 | 1 张 sheet / 12 帧 |

第 8 项说明：**整张 sheet 一次性降采样**保证帧格对齐，再逐帧修整；重点修轮廓和手脚像素，不追求完美。

## 3. 全局调色板

1. 以 Lospec 的 **Zughy 32**（32 色，柔和低饱和）为基底；
2. 允许追加最多 8 个自定义色（暖木色、花瓣粉、暖黄光晕等），总数 ≤ 40 色；
3. 定稿后导出为 `family_garden_palette_v1.png`（色板条图片），**8 张图全部只用这一个色板**，禁止任何图私加颜色；
4. 试产期间色板可调整，但每次调整后已完成的图要重新 remap 检查。

## 4. 像素密度规则（最重要的一条）

**全项目统一密度：1 美术像素 = 2 逻辑像素。** 所有物件按上表的美术像素档位作画，禁止某张图"画得更细"——混合密度是 converter 流水线最常见的翻车点，验收时逐张检查。物件在源图画布内的占比应 ≥ 80%。

## 5. Converter 参数建议

概念图继续用现有 `docs/08_art_prompt_library.md` 提示词生成（水彩概念图是好输入，不需要改提示词）。像素化两条路任选：

**路线 A：ImageMagick（可批量）**

```bash
# 物件（以记忆花为例）：盒式降采样 + 关闭抖动 + 重映射到全局色板
magick concept_flower.png -filter Box -resize 48x48 +dither -remap family_garden_palette_v1.png flower_raw.png

# 背景：先裁满 16:9 再降采样
magick concept_garden.png -filter Box -resize 640x360^ -gravity center -extent 640x360 +dither -remap family_garden_palette_v1.png bg_raw.png
```

**路线 B：Aseprite 内完成**：导入概念图 → `Sprite > Sprite Size` 缩到目标尺寸 → `Sprite > Color Mode > Indexed`（选定全局色板，Dithering 设 None）。

抖动原则：默认关闭，保持色块干净的"软像素"感；只允许在背景的天空/水面大渐变处用轻微抖动。

## 6. Aseprite / Piskel 修整标准

1. **轮廓**：物件外缘描 1 美术像素的深色轮廓，用同色系加深色，**不用纯黑**（软像素，不是硬核复古）；
2. **去噪**：清掉孤立杂点和抗锯齿糊边，同一材质表面色阶 ≤ 3 级；
3. **落点**：画布底边中点 = 物件落点；底部留白 ≤ 2 美术像素，水平居中（bottom_center 规则）；
4. **多状态一致**：记忆花三态、漂流瓶两态使用同一画布尺寸、同一基础轮廓，只改发光/花瓣/纸条等差异部分，叠放检查不跳动；
5. **可读性**：100% 和 200% 缩放下都能一眼认出是什么。

## 8. Godot 导入验证方式

由 C 配合执行（约 1 小时）：

1. 8 张图放入工程 `game/assets/px_trial/`（不覆盖任何现有资产）；
2. 在现有工程里临时摆放：背景 `Sprite2D` 置于 `(640, 360)` 且 `scale=(2,2)`，物件以 `scale=(2,2)` 摆在 16px 对齐的偶数逻辑坐标上（工程已是 Nearest 采样，无需改设置）；
3. 角色 sheet 换进现有 player（hframes=3 / vframes=4 不动），实际走两圈；
4. `python3 -m http.server` 起本地 Web 导出，手机横屏真机检查：边缘是否清晰、有无半像素错位、节点是否一眼可辨、三态切换是否跳动、行走动画有无帧间抖动。

## 9. 通过 / 不通过标准

**全部满足才算通过：**

1. 物件单张总耗时 ≤ 45 分钟，背景 ≤ 3 小时，角色 sheet ≤ 4 小时；
2. 8 张图 100% 使用全局色板、100% 符合密度规则；
3. 真机上节点可读、风格统一、三态切换无跳动、行走动画观感成立；
4. 团队三人看过真机效果后一致（或至少 2/3 同意且 A 认可）："这就是我们要的氛围"。

**半通过出口**：若 7 张静态图全过、唯独角色 sheet 转换不达标，不整体否决——改为角色用更低帧密度手绘重画（像素角色单帧很小，预算一天），其余按通过处理。

**任何静态资产条目不满足 = 不通过**，不做第二轮纠结。

## 10. 不通过的回退路线

1. 美术风格退回手绘水彩路线，`docs/08_art_prompt_library.md` 一字不改直接开始 P0 批量生产；
2. `docs/09` 仅回退第 2.1 条第 4 款（采样改 Linear，单独任务）与第 4/5/11 节的风格表述；slot/zone/footprint/manifest/ScenePortal 等系统规则全部保留；
3. 试产图归档到 `game/assets/references/px_trial/` 作参考，不删除；
4. 总损失 = 48 小时试产时间，不影响 6.16 三人并行开发排期。
