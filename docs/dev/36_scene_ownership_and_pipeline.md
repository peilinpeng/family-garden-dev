## 1. 协作模式:一人一场景,端到端负责

### 1.1 原则
- **以「场景」为认领单位**,不以「工序」为单位。认领了「鱼塘」,就负责鱼塘的:
  设计布局 → 出图(或对接美术出图)→ 搭 `.tscn` → 碰撞/遮挡 → 自测验收。
- 一个人**对自己的场景全程负责**,出问题找得到人,不会卡在「我交了你怎么没接」。
- 不互相改对方的场景文件。需要复用的东西(预制体、框架)走公共目录,见 1.3。

### 1.2 为什么这样分(而不是流水线)
场景制作高度耦合(出图位置直接决定锚点、碰撞、遮挡),拆成工序交接会产生大量来回对账;
一个人端到端做,信息不丢、迭代最快。**这是本项目场景制作的硬约定。**

### 1.3 边界(仍沿用 docs/dev/34)
- B(AI/内容安全)产物只在 `backend/`;场景制作属于 **C(游戏)**,产物只在 `game/`。
- **公共资产**(谁都能用、但不要乱改):
  - `scenes/prefabs/`(动态物件预制体,如 `DynamicNode.tscn`)
  - `scripts/managers/`(ScenePortal / SlotManager / NodeFactory 等框架)
  - 改公共资产要在群里说一声 + 记一行变更日志,别闷头改。

## 2. 美术出图规范(出图前必读)

### 2.1 画布与坐标(硬性,详见 docs/09)
- **画布固定 1280×720**(游戏逻辑分辨率)。所有整图都按这个尺寸。
- 像素风:**Nearest 采样,不缩放、不模糊、不加 mipmap**。
- 物件画在**它在场景里最终该出现的位置**上——不要居中、不要裁切。

### 2.2 一个场景要出三类图

**(A) 背景大图 `background.png`** —— 1 张
- 1280×720,**非透明**铺满。
- 包含:地板、墙、以及**所有"不需要遮挡玩家"的装饰**(贴墙画、不挡路的小物)。
- 能合进背景的就合进来,**省精灵、省性能**。

**(B) 单物件透明全画布图** —— 每个「要遮挡玩家」或「前景」的物件各 1 张
- 1280×720,**只有该物件有像素,其余 alpha=0 全透明**(就是你给我看的那种竹水器图 ✅)。
- 物件在图里的位置 = 它最终在场景里的位置(这样叠到背景上自动对齐)。
- **哪些要单独出**:
  - 玩家能走到其**背后被它挡住**的物件(桌、床、柜、灯笼、竹水器…)→ 进 y-sort 层。
  - **前景**:永远盖在玩家上方的(吊灯、高处垂下的枝叶)→ 进 Foreground 层。
- **哪些不用单独出**:不挡人的地板、贴墙装饰 → 留在背景大图里。
- 真透明,不是白底(Finder 缩略图显示白色只是预览,没关系)。

**(C) 碰撞引导图 `Collision_area.png`** —— 1 张(可选但强烈推荐)
- 1280×720。**挡路的地方涂实色(不透明)、能走的地方透明。**
- 只用来**生成碰撞**,玩家看不到它。形状不用精细,简化块状即可。
- 简单场景(如房间)可跳过它,直接在编辑器手画碰撞框更快(见 §4)。

### 2.3 命名与目录
- 每个场景一个目录:`game/assets/<场景名>/`(如 `assets/fishpond/`)。
- 背景固定叫 `background.png`(或 `scene_<场景>_bg_01.png`,与 manifest 一致)。
- 碰撞引导图固定叫 `Collision_area.png`。
- 单物件图用清晰英文名:`bamboo.png` / `dining_table.png`(**定了就别改名**,改名会断引用)。
- ⚠️ **禁止**对已入库 PNG 裁切/缩放/改色/重导出。要改尺寸先说。

## 3. 场景搭建流程(端到端,一个人走完)

> 没有「PS 图层自动变 .tscn + 自动碰撞」这种现成功能。下面第 4/5 步的"自动"指**跑脚本**,
> 不是引擎内置。技术细节见 docs/dev/35。

1. **设计**场景布局(承载什么记忆、玩家能干什么 —— 见 docs/02 §1)。
2. **出图**:按 §2 出背景 + 单物件图 + 碰撞引导图,放进 `assets/<场景>/`。
3. **导入**:把 PNG 拖进 Godot,自动生成纹理(确认 Texture Filter = Nearest)。
4. **搭 `.tscn`**(参考 `Kitchen.tscn` 结构):
   - 图层从下到上:`Background`(z=-300)→ `GroundProps/FixedBackVisuals`(玩家下)
     → `WorldYSort`(玩家 + 要遮挡的物件,开 `y_sort_enabled`)→ `Foreground`(z=1000,玩家上)。
   - 全画布底层:`Sprite2D` `centered=false, position=(0,0)`,直接叠。
   - 进 `WorldYSort` 的遮挡物件:用「**根节点放落地锚点 + Sprite2D 偏移 -锚点**」,
     根 `z_index=int(锚点y)`(详见 docs/35 §4.3)。动态生成的物件(记忆花/漂流瓶)
     用 `scenes/prefabs/DynamicNode.tscn` 实例化。
5. **生成基础碰撞**:从 `Collision_area.png` 跑脚本生成多边形,烘焙进 `.tscn`
   (脚本逻辑见 docs/35 §4.5)。**或**简单场景直接在编辑器手画。
6. **手调 + 自测**:编辑器里 Debug ▸ Visible Collision Shapes,按 §5 自查。

## 4. 碰撞 & 遮挡的原则(最容易做错)

- **碰撞只圈"地面占地"**,不要描整件家具的视觉轮廓(椅背/扶手/阴影别框进去),否则碰撞过大。
- **碰撞要挡住物件主体**,别只挡底边——否则玩家会走进物件内部、被它遮住,看着像"图层穿帮"
  (其实是碰撞太小)。这是踩过的坑。
- **碰撞别从美术图的不透明边缘自动描**(轮廓=太大且易出错);要从专门的 `Collision_area.png` 生成。
- **遮挡不是"画一个区域"**,而是在**出图时就决定**:把"要挡人的物件"单独出成透明图、放进
  `WorldYSort`,引擎按落地点 Y 自动排前后。第 6 步只微调锚点。
- 简单房间(家具都在背景里、不需要走到家具背后)**可以完全不做遮挡**,只做碰撞即可。

## 5. 自查验收清单(交付前自己过一遍)
- [ ] 场景能跑,无脚本报错 / 无资源丢失 / 无 `Convex decomposing failed`。
- [ ] 所有图与背景**像素级对齐**,无偏移、无缩放模糊、无色差。
- [ ] 玩家在可走区能动;**撞不进**该挡的物件;不被错误地卡住。
- [ ] 需要遮挡的物件:走上方被挡、走下方在前,前后自然。
- [ ] 前景(灯/枝叶)始终盖在玩家上方;地面阴影/水面始终在玩家下方。
- [ ] Debug ▸ Visible Collision Shapes:碰撞框不明显过大、不挡路、不穿模。
- [ ] 出入口(若有 ScenePortal):走入和点按都能切换,落到正确 spawn 点(docs/09 §14)。

## 7. 常见坑速查
- 物件图不是 1280×720 / 物件没画在最终位置 → 叠上去错位。
- 用了白底而非透明 → 物件四周一块白。
- 碰撞太小 → 走进家具被遮,误以为图层坏了。
- 想要遮挡却把家具留在背景大图里 → 永远做不出遮挡(必须单独出图)。
- 改了已入库 PNG 的名字/尺寸 → 断引用、错位。
