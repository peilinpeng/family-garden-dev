# 05｜团队分工与技术说明

## 对外项目短版

Family Garden 是一个以家庭记忆为核心的 AI 治愈系游戏。它把照片、留言、房间记忆和
旅行经历转化为可探索的数字花园。AI 不替家人编故事，而是帮助整理已有内容、提出温和
问题，让家庭成员在低压力的游戏空间中自然分享和回应彼此。随着上传、回答和共同照料，
花园里会长出记忆花、藤蔓、漂流瓶、共享农田和个人房间。

## 对外项目长版

很多家庭并不是联系不上，而是不知道如何自然交流。父母和子女之间常常停留在“吃饭了
吗”“最近怎么样”的浅层对话，大量家庭照片、旅行经历和长辈故事也散落在手机相册和
聊天记录里，难以沉淀。

Family Garden 希望创造一个线上家庭第三空间。用户可以上传照片、留言、明信片或房间
照片，AI 会帮助整理成可编辑的记忆卡片，并提出温和、开放的问题，引导家庭成员继续补充
故事。被补充的记忆会在花园、鱼塘、共享农场和个人房间中长成可点击、可回应的节点。

在这里，AI 不是故事编造者，而是记忆整理助手；游戏也不是装饰层，而是家庭互动真实
发生的媒介。家人不需要被要求严肃谈心，也能通过发现、种植和共同照料重新认识彼此的
记忆。

## 技术亮点

1. 统一 AI 契约：四项 AI 能力共享 Schema 校验、状态、缓存、取消、错误分类与 fallback；
2. 内容安全边界：AI 只基于用户输入整理，不推断关系；安全错误 fail-closed，不被 mock 掩盖；
3. 安全场景生成：模型只输出语义物件和 zone，Godot 通过白名单目录生成坐标和 TileMap；
4. 家庭级数据隔离：数据网关按身份和 `family_id` 限制访问，客户端不持有服务端密钥；
5. 多人共享闭环：成员在线状态、场景事件与共享农场更新通过实时中继通知；
6. 可演示韧性：真实云端、离线 mock、空存档种子和明确错误恢复共同保证核心体验可用。

## 团队分工

项目采用“产品美术、场景搭建、系统端到端”协作方式：

| 方向 | 职责 |
|---|---|
| 产品统筹与美术体验 | 产品定位、体验节奏、视觉资产、比赛材料和场景气质 |
| 场景设计与搭建 | `.tscn`、美术摆放、碰撞、遮挡、Y-Sort 和场景布局 |
| 系统 / 数据 / 后端 / AI | Godot 功能入口、CloudBase、混元接入、契约校验、内容安全、同步和功能 UI |

实际姓名、学校/公司与联系方式只在比赛平台填写，不写入公开源码文档。

## 架构说明

Godot 客户端负责交互、可视化、状态管理和受控场景生成；CloudBase AI Gateway 负责密钥
保护、内容安全、prompt 和混元调用；Data Gateway 负责家庭数据隔离与持久化；Storage
保存家庭照片；Presence Relay 只传递在线成员和轻量刷新事件。客户端无法直接读取服务端
密钥，AI 结果进入游戏前还要再次通过契约与白名单校验。

## 评委常见问题

**AI 是否会编造家庭故事？**  不会。生成卡片可编辑，事实只来自用户输入；模型用于整理、
提问和语义识别。

**为什么不直接生成一张房间图片？**  图片难以交互，也无法保证可走区域。语义结果进入
受控素材库后，生成的是可探索、可持久化的游戏房间。

**多人功能体现在哪里？**  家庭成员共享记忆、农场地块和聊天数据，并能看见在线成员及
所在场景；一个成员更新后，其他成员收到轻量刷新。

**没有网络还能玩吗？**  已同步内容和本地场景仍可浏览；AI 技术故障有明确 fallback，
但鉴权和内容安全错误不会被绕过。
